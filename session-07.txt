human user -> username/password or username/key
if we use human/root user to run the application

1.  they have more access in Linux, if one server is compromised their credentials are leaked. more priveleges issue
2. if hacked, blast radius is more
3. more files and more folders are on human names
4. what if the human resigns from company?
5. auditing and accountability

instead of running applications or services on human credentials we use system user to limit blast radius and least priveleges. system users will not have interactive logins, so no credentials, no login, no shell/terminal access also

useradd --system --home /app --shell /sbin/nologin --comment "expense system user" expense

[Unit]
Description=Expense Backend Service
After=network.target

[Service]
User=expense
Environment=DB_HOST=172.31.0.54
Environment=DB_USER=expense
Environment=DB_PWD=ExpenseApp@1
Environment=DB_DATABASE=transactions
ExecStart=/bin/node /app/index.js
SyslogIdentifier=backend
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

systemctl start backend

2. search for backend.service
3. execute the start script and inject the environment
4. User info also will be there to run the service
